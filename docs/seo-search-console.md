# راهنمای سئو، سرچ کنسول و انتشار لیفت تایر

تاریخ نگارش: ۲۰ آبان ۱۴۰۵ (۱۱ نوامبر ۲۰۲۶)

## چه چیزی در این مخزن منتشر می‌شود؟

این مخزن متعلق به **لیفت تایر** است، نه وب‌سایت خودرو چاره. گزارش معرفی خودرو چاره در مسیر `/blog/khodro-chare-national-automotive-services` لیفت تایر قرار گرفته و به `https://khodrochare.ir/` پیوند می‌دهد. در این متن، «پروژه ملی» توصیف چشم‌انداز اعلام‌شده مجموعه است؛ ادعای تأیید دولتی یا امکان اعزام قطعی به همه شهرها مطرح نشده است. محدوده و ظرفیت هر خدمت باید از خود خودرو چاره استعلام شود.

نشان خودرو چاره از [فایل نشان موجود در مخزن متعلق به همان مجموعه](https://github.com/amirabbasly/khodrochare/blob/main/public/images/khodrochare-logo-compact.webp) برداشته شده است. نشانی ویرگولِ ارائه‌شده در مقاله به‌عنوان منبع معرفی لینک شده، اما متن کامل صفحه ویرگول در زمان این بررسی از ابزار خواندن صفحه قابل دریافت نبود؛ بنابراین برای جزئیات آن ادعای مستقلی نشده است.

این مطلب صریحاً «رپورتاژ» معرفی می‌شود و لینک‌های تبلیغاتی خودرو چاره `rel="sponsored"` دارند. پس از انتشار عمومی لیفت تایر، این پیوند روی دامنه‌ای متفاوت از مقصد قرار می‌گیرد؛ تا پیش از انتشار، بک‌لینک زنده یا شناسایی‌شده توسط گوگل محسوب نمی‌شود. گوگل لینک‌های تبلیغاتی را طبق [راهنمای تعیین رابطه لینک‌ها](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links) عموماً مانند لینک تحریریه‌ای عادی دنبال نمی‌کند؛ رتبه یا اعتبار مشخصی تضمین نیست. برای انتشار در رسانه‌های دیگر باید با همان رسانه هماهنگ و ماهیت تبلیغاتی شفاف اعلام شود.

## ثبت لیفت تایر در Google Search Console

1. بعد از انتشار روی دامنه واقعی و فعال‌شدن HTTPS، وارد [Google Search Console](https://search.google.com/search-console) شوید و **Add property** را انتخاب کنید.
2. برای پوشش همه زیر‌دامنه‌ها و HTTP/HTTPS، نوع **Domain** را انتخاب و فقط `lift-tire.com` را وارد کنید؛ بدون `https://` و بدون مسیر. اگر دامنه نهایی متفاوت است، دامنه واقعی خودتان را وارد کنید.
3. سرچ کنسول یک رکورد تأیید می‌دهد. در مدیریت DNS دامنه یک رکورد **TXT** با نام `@` (یا نام خالی، طبق پنل DNS) و مقدار دقیق داده‌شده از سوی گوگل اضافه کنید. رکوردهای TXT موجود را حذف نکنید. تا انتشار DNS صبر کنید، **Verify** را بزنید و رکورد را بعد از تأیید نگه دارید. راهنمای رسمی: [تأیید مالکیت](https://support.google.com/webmasters/answer/9008080?hl=en).
4. در منوی **Sitemaps**، نشانی `https://lift-tire.com/sitemap.xml` را ثبت کنید. اگر دامنه واقعی فرق دارد همان دامنه را جایگزین کنید. وضعیت دریافت و خطاها را در همین بخش بررسی کنید.
5. در **URL inspection** صفحه اصلی، `/blog`، رپورتاژ و یکی از راهنماهای تازه را بررسی کنید. پس از مشاهده نسخه زنده، در صورت نیاز **Request indexing** را بزنید. ثبت نقشه یا درخواست خزش، ایندکس یا رتبه را تضمین نمی‌کند؛ [راهنمای نقشه سایت گوگل](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
6. طی هفته‌های بعد گزارش **Page indexing**، **Performance** و **Core Web Vitals** را بررسی کنید. ابتدا داده واقعی جمع‌آوری کنید، سپس نمایش، کلیک، CTR و صفحات دارای خطا را مقایسه کنید؛ از اعلام رتبه یا رشد بدون داده خودداری کنید.

### روش جایگزین برای URL-prefix

اگر DNS در دسترس نیست، می‌توانید یک property از نوع **URL-prefix** برای `https://lift-tire.com/` بسازید و روش HTML tag را انتخاب کنید. فقط مقدار `content` تگ ارائه‌شده توسط گوگل را در فایل `.env` سرور، در متغیر `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` بگذارید؛ خود تگ کامل را وارد نکنید. مقدار واقعی را در مخزن یا گفت‌وگو منتشر نکنید. پس از تغییر این متغیر یا `NEXT_PUBLIC_SITE_URL`، بیلد مجدد لازم است؛ خروجی HTML صفحه اصلی باید متاتگ `google-site-verification` را نشان دهد. این روش فقط همان پیشوند URL را پوشش می‌دهد، نه تمام زیر‌دامنه‌ها. روش DNS برای property نوع Domain مناسب‌تر است.

**خودرو چاره property جداگانه دارد:** برای `khodrochare.ir` نیز جداگانه در همان حساب Search Console یک Domain property بسازید، رکورد DNS مربوط به خودش را ثبت کنید و نقشه سایت خودش را ارسال کنید. تنظیمات این مخزن نقشه سایت یا مالکیت دامنه خودرو چاره را تغییر نمی‌دهد.

## یادداشت استقرار و کنترل پس از انتشار

انتشار یک شاخه یا اجرای پیش‌نمایش، انتشار روی سرور واقعی نیست. در زمان این تغییر، دسترسی به سرور تولید، DNS یا Search Console در محیط توسعه در اختیار نبود. ابتدا تغییرات این شاخه باید از مسیر انتشار مورد تأیید پروژه به کد قابل دریافت سرور برسند. روی سرور موجود، پس از گرفتن بکاپ و تأیید نسخه صحیح کد، مطابق روش نصب فعلی عمل کنید:

```bash
cd /var/www/lift-tire.com          # یا مسیر واقعی نصب
./deploy.sh backup                 # برای نصب Docker موجود
# ابتدا بررسی کنید کد منتشرشده مورد نظر روی شاخه فعلی سرور قابل دریافت است.
git log -1 --oneline
./deploy.sh update
./deploy.sh status
curl -I https://lift-tire.com/blog
curl -s https://lift-tire.com/robots.txt
curl -s https://lift-tire.com/sitemap.xml | grep 'khodro-chare-national-automotive-services'
```

`deploy.sh update` شاخه فعلی سرور را pull می‌کند و در صورت خطای pull ممکن است با کد قبلی ادامه دهد؛ حتماً commit مورد انتظار را بعد از pull و قبل از اعلام موفقیت بررسی کنید. برای نصب PM2، راهنمای `docs/DEPLOY-ubuntu.md` و `scripts/deploy-pm2.sh` را دنبال کنید. دستورهای `seed --force` یا `destroy` را برای انتشار این تغییر اجرا نکنید؛ داده‌های فروشگاه را حذف می‌کنند. پیش از انتشار نهایی، HTTPS، هدایت دامنه، پاسخ ۲۰۰ صفحه، متن، لوگو، لینک خارجی، متا و sitemap را از خارج سرور بررسی کنید.

## جزئیات فنی و نگهداری

- `NEXT_PUBLIC_SITE_URL` باید آدرس عمومی canonical بدون مسیر و با پروتکل صحیح باشد؛ مقدار اشتباه، canonical، Open Graph، schema و sitemap را هم اشتباه می‌کند.
- مقاله‌های تحریریه جدید در `frontend/lib/editorial-posts.js` نگهداری می‌شوند و بدون پاک‌کردن دیتابیس در کنار مقالات منتشرشده پنل نمایش می‌یابند. اگر در پنل مقاله منتشرشده‌ای با همان slug بسازید، محتوای پنل اولویت دارد. این مقالات فایل‌محور هستند و برای حذف کامل خود فایل نیز باید ویرایش شود.
- سه متن نمونه قدیمی فقط وقتی محتوایشان دقیقاً همان seed دست‌نخورده باشد با نسخه اصلاح‌شده نمایش داده می‌شوند؛ متن تغییر‌داده‌شده مدیر دست‌نخورده می‌ماند. متن‌های پنل باید از نظر علمی، تاریخ و اصالت مرتب بازبینی شوند.
- لینک‌ها و HTML مقاله پیش از نمایش پالایش می‌شوند. داده ساختاریافته Article، Breadcrumb، Organization، WebSite و Product بدون امتیاز ساختگی ساخته می‌شود. قیمت محصول از تومان رابط کاربری به ریال schema تبدیل می‌شود. قیمت و موجودی باید همیشه با داده واقعی فروشگاه منطبق باشند.
- صفحات صفحه‌بندی‌شده canonical مستقل دارند؛ فیلترها و جست‌وجوهای دلخواه فروشگاه `noindex, follow` هستند. صفحات سبد، حساب، پرداخت و پیگیری نیز `noindex` هستند. robots.txt جایگزین احراز هویت و حفاظت اطلاعات نیست.
- نقشه محصولات همه صفحه‌های API را می‌خواند، نه فقط ۶۰ محصول اول. اگر API در دسترس نباشد، URL محصولات نمایشی که صفحه واقعی ندارند به نقشه افزوده نمی‌شوند. برای بیش از ۵۰ هزار URL باید نقشه به چند فایل تقسیم شود.
- دیتای پیش‌فرض، امتیازها، شماره‌ها، سفارش و درگاه پرداخت این پروژه نمونه/شبیه‌سازی هستند. پیش از هر انتشار تجاری، داده و ادعاهای واقعی، دسترسی مدیر و درگاه واقعی را جداگانه تأیید و جایگزین کنید؛ داده ساختاریافته جایگزین این بررسی نیست.

# گزارش اجرای بهینه‌سازی SEO لیفت تایر

## وضعیت و دامنه

مبنای بررسی این دور، commit `7c7475d` در شاخه کاری پروژه بود. این گزارش درباره کد و پیش‌نمایش محلی است؛ سرور تولید، DNS و Search Console در دسترس نبوده و هیچ استقرار یا درخواست ایندکس انجام نشده است. صفحه زنده رپورتاژ و لینک خودرو چاره قبلاً از خروجی عمومی دیده شده‌اند؛ چهار مسیر تازه این دور در همان بررسی صفحه «۴۰۴» نشان دادند، اما کد عددی پاسخ زنده توسط ابزار خواندن صفحه ثبت نشد. گزارش کامل‌تر: [URLها و وضعیت محلی/زنده](seo-url-report.md).

## کارهای انجام‌شده

- ممیزی معماری Next.js/Express، داده PostgreSQL/PGlite، مسیرها، metadata، sitemap، robots، schema، تصاویر، ریسک‌های عملکرد و روش‌های استقرار احتمالی؛ [گزارش اولیه و ریسک‌ها](seo-audit-baseline-2026-11-11.md).
- [بررسی کیفی رقبا و نقشه کلمات](seo-competitor-review.md) با اتکا به صفحات قابل مشاهده و منابع سازنده، بدون جعل رتبه، حجم، سختی، ترافیک یا بک‌لینک. [تقویم ۳۰ موضوع](seo-content-calendar.md) شامل دو مقاله آماده و ۲۸ پیشنهاد منتشرنشده است.
- دو راهنمای مستقل برند بارز و کویر و دو مقاله شاخص بار/سرعت و سایش؛ نمایش محصولات فقط از API، لینک به منابع سازنده و هشدار درباره لزوم تطبیق تیپ و سال خودرو. برای دو مقاله هنوز تاریخ انتشار عمومی در صفحه یا schema ادعا نشده است.
- بهبود مجله موجود، رپورتاژ خودرو چاره، راهنمای سه دسته اصلی، لینک‌های مرتبط برند/دسته/مقاله و metadata فهرست‌ها. سه متن seed فقط در صورت تطابق دقیق با محتوای نمونه اصلاح می‌شوند؛ متن تغییر‌داده‌شده مدیر و URLهای قبلی حفظ می‌شوند.
- metadata غیرنمایشی صفحه اصلی و پیش‌فرض به متن خنثی‌تر بدون وعده تأییدنشده تغییر کرد. بخش‌ها، محتوای قابل مشاهده، چیدمان و انیمیشن‌های معمول صفحه اصلی تغییر داده نشدند؛ خطای hydration قدیمی در تنظیم «کاهش حرکت» به‌صورت فنی اصلاح شد. برای حفظ ظاهر، ادعاها و داده‌های قدیمی قابل مشاهده صفحه اصلی حذف نشده‌اند و باید توسط مالک تأیید شوند.
- روی صفحات کالا، شمارنده تبلیغاتی و چند ادعای ثابتِ تأییدنشده حذف شدند؛ چهار نظر دقیق seed پالایش و میانگین فقط از نظرهای تأییدشده باقی‌مانده محاسبه می‌شود. اصالت نظرهای باقی‌مانده به‌طور مستقل تأیید نشده است. اگر قیمت نامشخص باشد پیشنهاد schema و خرید غیرفعال است؛ اگر موجودی نامشخص باشد availability ساختگی صادر نمی‌شود. قیمت تومان در schema به ریال تبدیل می‌شود. تغییری در دیتابیس یا درگاه پرداخت انجام نشده است.
- canonical مستقل برای صفحات معتبر صفحه‌بندی و `noindex, follow` برای فیلترهای دلخواه؛ ۴۰۴ برای صفحه‌بندی خارج از محدوده هنگام دسترسی صحیح به API. در اختلال API، دسته/محصول به‌جای ۴۰۴ کاذب خطای سرور می‌دهند. sitemap در خطای صفحه اول یا بعدی محصولات، پاسخ نامعتبر pagination، دسته یا مقاله خطا می‌دهد تا نقشه ناقص منتشر نشود. قطع CMS مجله را موقتاً خطای سرور می‌کند تا محتوای مدیر با نسخه نمونه اشتباه جایگزین نشود؛ fallback قبلی صفحه اصلی حفظ شده است. این انتخاب یک مصالحه در دسترس‌پذیری است و باید با مانیتورینگ همراه شود.
- برای تایید مالکیت Google دو روش DNS و متاتگ اختیاری، و راهنمای روشن تفکیک انتشار، حضور در sitemap، کشف، خزش و ایندکس تهیه شد. برای Docker و PM2 [رانبوک مشروط، بکاپ، ثبت نسخه، لاگ و بازگشت](seo-deploy-runbook.md) آماده و توصیه‌های خطرناک به‌روزرسانی قدیمی علامت‌گذاری شدند.

## آزمایش‌های انجام‌شده

| آزمون | نتیجه و محدوده |
|---|---|
| build frontend | `npm run build` موفق؛ خروجی Next.js standalone. build طبق پیکربندی پروژه lint را اجرا نمی‌کند. |
| lint مستقل | `npm run lint` با کد خروج صفر و **۴۳ هشدار**؛ دو قاعده لینک قدیمی فقط در `about/page.js` و `SizeGuideCard.jsx` به هشدار تبدیل شده‌اند. رفع کامل هشدارها انجام نشده است. |
| تست ادغامی SEO | **۱۳/۱۳** موفق با API ساختگی: مجله و CMS، لینک sponsored، metadata/schema، همه صفحات محصولات sitemap، خرابی API/صفحه اول و دوم و pagination نامعتبر، صفحات برند/دسته، داده نامشخص، noindex و حفظ محتوای مدیر. |
| تست API | **۲۹/۲۹** با backend واقعی و پایگاه PGlite موقت و مجزا؛ شامل سفارش و پرداخت **شبیه‌سازی‌شده فقط در محیط آزمایش**، نه سفارش یا پرداخت واقعی. |
| مرورگر Chromium | صفحه اصلی، فروشگاه، دسته سواری، دو برند، یک محصول نمونه، مجله، دو مقاله تازه و رپورتاژ در عرض‌های ۳۹۰ و ۱۴۴۰ پیکسل پاسخ ۲۰۰ و H1/RTL داشتند؛ در این نمونه‌ها overflow افقی صفحه مشاهده نشد. سبد خرید روی داده نمونه محلی بررسی شد. |
| صفحه اصلی و تعامل | با همان API آزمایشی، عکس و DOM با نسخه مبنا مقایسه شد؛ ساختار و محتوای اصلی در بررسی مقایسه‌ای حفظ شدند. در حالت کاهش حرکت خطای قدیمی React در مبنا بازتولید شد و در نسخه جدید دیده نشد. منوی موبایل، جست‌وجوی موبایل و تغییر اسلاید در حالت معمول/کاهش حرکت، و تغییر اسلاید دسکتاپ تست شدند. این آزمون محدود به مرورگر و اندازه‌های یادشده است. |
| URLها و کنترل diff | پاسخ، canonical، robots و sitemap برای ۴ URL تازه، ۲۴ صفحه/حالت موجود و ۲۰ محصول **نمونه** در [گزارش جداگانه](seo-url-report.md) ثبت شد؛ `git diff --check` بدون خطای فاصله‌گذاری بود. |

این‌ها سنجه میدانی Core Web Vitals، تست پرداخت واقعی، تست جامع دستگاه‌ها، حساب‌های واقعی یا صحت داده کسب‌وکار نیستند. در تلاش آزمایشگاهی مرورگر محلی، LCP و حجم انتقال از API مرورگر مقدار قابل اتکایی ندادند؛ بنابراین امتیاز سرعت یا مقایسه بهبود گزارش نمی‌شود. داده آزمایشی و build در محیط محلی‌اند و نباید به تولید منتقل شوند.

## اولویت‌های باقی‌مانده پیش از فروش یا انتشار

۱. **امنیت سفارش:** در کد فعلی `GET /api/orders/:code` بدون احراز هویت، رکورد کامل سفارش و اقلام را می‌دهد. `noindex` محافظ داده نیست. برای طراحی سازگار با رهگیری مهمان/پرداخت و کنترل دسترسی، بررسی و تأیید فوری مالک لازم است؛ در این دور جریان سفارش را تغییر ندادیم.
۲. **پرداخت:** درگاه repository شبیه‌سازی‌شده است؛ اتصال و تأیید درگاه واقعی و تست امن آن پروژه‌ای جداگانه است. موفقیت تست mock اثبات پرداخت بانکی نیست.
۳. **داده تجاری:** seed شامل محصولات، امتیاز، شرح کالا، تماس و ادعاهای نمایشی است؛ در صفحه اصلی و اطلاعات API همچنان ممکن است چنین متن‌هایی دیده شوند. مالک باید کاتالوگ، تاریخ تولید، قیمت، موجودی، سازگاری، ضمانت، نظرات، شماره‌ها و قابلیت ارسال را با منابع واقعی تأیید کند. مقدار صفر در پایگاه می‌تواند پیش‌فرض باشد و از قیمت تأییدشده قابل تمایز نیست؛ برای کالاهای صفرقیمت هم بازبینی مالک لازم است. فیلترکردن چهار نظر شناخته‌شده اثبات واقعی بودن بقیه نیست.
۴. **عملیات:** روش تولید و نسخه دقیق زنده نامعلوم است. در PM2 اگر تنظیم PostgreSQL نامعتبر باشد، ecosystem می‌تواند به PGlite fallback کند؛ نوع و محل پایگاه را قبل از هر انتشار تأیید کنید. بکاپ و rollback قابل آزمون لازم‌اند؛ اسکریپت‌های قدیمی update/restart را بدون اصلاح و ارزیابی اجرا نکنید.
۵. **پایش:** اندازه‌گیری واقعی LCP/INP/CLS، وضعیت Rich Results، داده عملکرد و ایندکس در Search Console و تحلیل کیفیت بک‌لینک‌ها بعد از دسترسی معتبر و انتشار انجام شود؛ هیچ نتیجه یا رتبه‌ای تضمین نمی‌شود. نقشه اکنون در هر درخواست کاتالوگ را از API می‌خواند؛ بار آن باید پایش و در کاتالوگ بزرگ‌تر از محدودیت sitemap فایل‌ها تقسیم شوند. در قطعی API، فهرست فروشگاه و راهنمای برند ممکن است با پیام عدم دسترسی پاسخ ۲۰۰ بدهند؛ قطع طولانی و خطر soft-404 نیازمند پایش است.
